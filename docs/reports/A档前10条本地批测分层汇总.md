## 解读（服务扩量战略）

1. **环境供给可用（主粮前提成立）**  
   10/10 拉起成功：有 compose 的库存不是瓶颈。

2. **利用转化是主瓶颈**  
   证据率仅 20%：多数 HTTP 来自 search/exploit-db/nuclei，与本地靶场不贴合。

3. **DB 金标准可重复**  
   2122、1058 再次闭环；编号少但稳。

4. **远程搜索噪声大**  
   外链/wayback 502、搜索候选拖满超时；批测应 **优先 local_kb，限制远程搜索**。

5. **下一步**  
   - A 档：强制/优先 local_kb，缩小 search  
   - C 档（79 条）：补 README/custom PoC 再入队  
   - HTTP：做 PoC-环境贴合，而不是扩搜索面  
   - 汇报继续用分层指标（env / exec / evidence / archive）

## 后续优化：local_kb 优先（已落地）

针对本试点「search 噪声大、单 CVE 易超时」，已改：

| 项 | 行为 |
|---|---|
| `--local-container` | 默认 **不** 走 reference/web_search/exploit-db 等远程源 |
| 配置 | `LOCAL_CONTAINER_ALLOW_REMOTE_SEARCH=false`（默认）；`LOCAL_CONTAINER_MAX_REQUESTS_PER_CVE=6` |
| 路由 | local_kb 命中 → 直接 verify；本地候选用尽 → generate_report |
| 仍允许 | 本地 nuclei 模板（无 local_kb 时） |

**复测（4 条，local_kb 优先后）：**

| CVE | 结果 | phases_tried | 耗时 |
|---|---|---|---:|
| CVE-2012-2122 | 数据库命中 | `local_kb_search` | ~130s |
| CVE-2018-1058 | 数据库命中 | `local_kb_search` | ~115s |
| CVE-2014-3704 | 发包服务失败（本地 vulhub http，未再远程发散） | `local_kb_search` | ~90s |
| CVE-2010-3863 | 发包服务失败（local_kb_pcap，未再远程发散） | `local_kb_search` | ~71s |

明细：`output/queue/A_local_kb_priority_retest.json`  

结论：DB 金标准不回归；HTTP 失败更快收敛，不再被 search/wayback 拖满超时。下一步应修 HTTP 发包/PoC 贴合，而不是恢复远程盲搜。
